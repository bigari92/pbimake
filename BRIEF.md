# Cloud agent brief

Your job is to make this engine run correctly and unattended on Linux, and to
give it the two things it has never had: an ingest contract and a regression
net. Work in the order below — each task depends on the one before it.

Read `README.md` first for the layout and the known-gap list. This file says
what to do about them.

## Your environment, and the honest limits of it

You are on Linux. There is no Power BI Desktop, no Windows, and no Microsoft
fonts. That shapes what "done" can mean:

- **You cannot confirm how anything renders.** Every claim you make must be
  checkable in the emitted JSON/TMDL. Never write "this now displays correctly"
  — write "the visual.json now carries `labelDisplayUnits: 1`".
- `powerbi_is_open()` returns `False` here because `tasklist` does not exist and
  the call is wrapped in `try/except` (`tmdl_editor.py:40-50`). That is correct
  behaviour on Linux. **Do not "fix" it.**
- `icon_generator._glyph_font` raises `FileNotFoundError` without Segoe MDL2
  Assets. That refusal is deliberate — a substituted font renders tofu boxes
  rather than icons. **Do not swap in another font.** Skip icon paths in tests
  and flag the decision; whether to ship PNG glyphs or move to an open icon
  font is the owner's call, not yours.
- `bg_generator` falls back to `ImageFont.load_default()` without Segoe UI, so
  background geometry here will not match a Windows render. **Do not tune pixel
  offsets against that fallback** — you would be calibrating to the wrong font.
- Never commit data. Fixtures are generated; `.gitignore` enforces it.

Do not touch `themes/`, `pbip_template/`, or `_data/brand_styles.json` unless a
task says so.

## Task 1 — a test fixture. Blocks everything else.

There is currently **no regression net**. Sections 1-2 of `tests/_test_v2.py`
compare generated output against a project Power BI Desktop produced itself,
which does not exist here; unset `PBIMAKE_ECOM_DIR` makes them fail rather than
skip.

Build an in-repo fixture:

1. `tests/fixtures/make_fixture.py` — generate data with
   `tests/generate_data.py`, scaffold a project, add a representative spread of
   measures and visuals (at minimum: card, kpi_tile, bar, line, funnel,
   scatter, treemap, table).
2. Commit golden copies of the resulting TMDL and `visual.json` files under
   `tests/fixtures/golden/`.
3. Rewrite sections 1-2 of `_test_v2.py` to read the fixture. Remove
   `PBIMAKE_ECOM_DIR` entirely once nothing needs it.
4. Make `tests/_test_design.py` run green too.

**Be clear about what this buys.** Golden files generated by our own code
cannot prove we match what Power BI expects — only that we have not *changed*.
The `ECOM` comparison existed to check against a real Desktop-authored project,
and nothing you can do on Linux replaces it. Say so in the PR. Correctness
against Power BI stays a Windows job.

Done when: both suites pass with no environment variables set, and a deliberate
one-property change to any builder makes a golden test fail.

## Task 2 — backport the five patch scripts

The reference dashboard needed five post-build `patch_*.py` passes, which means
**a plain `build_from_spec` does not reproduce the shipped artifact**. Those
scripts are not in this repo; their findings are reproduced below in full.
Treat each as a spec: write the failing test first, then fix the builder.

### A. `labelDisplayUnits` is almost never emitted

Only two occurrences exist: `pbir_editor.py:897`, inside `add_kpi_tile`
(`:835`) and gated behind `display_units == "none"`; and `:1274`. Nothing else
emits it, so Power BI applies its own `Auto` and rounds.

Two real misreports this caused:

- **Cards.** `add_card_measure` (`:795`) emits none. A measure formatted
  `EUR#,0` still rendered **€2M** for a true value of **€1,740,783**. On a fee
  total that is not a rounding nicety, it is a wrong number.
- **Chart data labels.** A funnel rendered `4K / 2K / 1K / 0K / 0K` — two
  different stages both showing `0K`. True values: 4,300 / 1,534 / 738 / 310 /
  223.

Fix: emit `labelDisplayUnits` in `add_card_measure` and in the chart builders
(`_objs_bar` `:468`, `_objs_column` `:485`, `_objs_line` `:493`, `_objs_pie`
`:503`, `_objs_funnel` `:509`, `_objs_treemap` `:526`). `_lit_num(1)` already
yields the right literal for "None". Make it overridable per visual, defaulting
to None rather than Auto — a dashboard that silently rounds is worse than one
that shows a long number.

### B. The funnel's category axis is switched off

`_objs_funnel` (`:509`) sets, at `:513`:

```python
"categoryAxis": [{"properties": {"show": _lit_bool(False)}}],
```

In a Power BI funnel the **category axis** is what renders stage names down the
left edge — `categoryLabels` does not substitute for it. Switching it off is
sensible for a bar chart and wrong for a funnel: it left every bar anonymous, so
a viewer saw `1,534` without knowing it meant "Screened".

Fix: `show: True` for funnels specifically. Do not change the bar/column
builders, where off is correct.

### C. The scatter has no category labels and no bubble size

`_objs_scatter` (`:516-523`) sets `labels show=False` and emits neither
`categoryLabels` nor `bubbleSize`. Six anonymous bubbles: a reader could see
someone hiring at 7.5% in 32 days but not who. Extreme points were also clipped
by the plot edge.

Fix: `categoryLabels show=True`, and a `bubbleSize` default small enough that
outliers stay inside the plot area.

### D. A malformed format string was accepted silently

`"EUR#,0,,.2M"` was passed as a measure format and rendered **€0MM**. Each
comma scales by 1000 and `.2M` is not a decimal spec. Nothing rejected it.

Fix: validate `format_string` in `tmdl_editor.add_measure` and reject patterns
that cannot be meant — multiple consecutive scaling commas followed by a
decimal spec is the clearest case. A wrong format is indistinguishable from a
wrong number to whoever reads the dashboard.

Done when: a fixture rebuild emits all of the above with no post-processing,
each one covered by a test asserting the property in the JSON.

## Task 3 — `csv_contract.py`

The largest piece, and the one the product does not currently have at all.
There is no cleaning module anywhere; ingest is bespoke per project.

The failure it must stop is silent. `pbip_scaffold.py:56` passes pandas'
column names straight into the generated M. A blank header becomes
`Unnamed: 6` in pandas and `Column7` in Power Query; the type map then matches
nothing and refresh dies — **and both gates still print `NAMES OK` and
`ALL VALID`**, so nothing catches it until a human opens the file.

Required:

| Check | Behaviour |
|---|---|
| Encoding, BOM, delimiter | sniff; record what was chosen |
| Control characters | strip, and report that you did |
| Blank headers | refuse until named or dropped — never auto-number |
| Duplicate headers | refuse until renamed; Tabular rejects them anyway |
| Types | validate over the **whole file**, widen on conflict |
| Dates | pin culture against the model's `en-US`; count ambiguous rows and make the caller choose |
| Ragged rows | explicit policy — reject the file or drop the rows, never silently |

Output a structured rejection report, not an exception trace. A file that
cannot be modelled correctly must be refused with a reason a non-programmer can
act on.

Then a corpus test: at least 20 real public CSVs (Kaggle, data.gov — you have
network access), deliberately including a cp1251 file, a GA4 export, a ragged
file, and one large enough that a type changes after row 5,000. Target: **zero
silently-wrong, zero unhandled tracebacks.** Log every file you dropped from the
corpus and why — a silent cap reads as full coverage.

## Task 4 — mechanical fixes

Small, independent, do them last or alongside.

- `sys.stdout.reconfigure(encoding="utf-8")` at import. Console output mangles
  em-dashes under cp1252 today (`NAMES OK â€" 1 model(s)`).
- `pbip_scaffold._m_escape` (`:109`) escapes `"` but not `#(`, which M treats as
  the start of an escape.
- `pbip_scaffold.new_project` leaves a half-written directory when it fails, and
  the resulting `FileExistsError` then blocks every retry. Wrap in `try/finally`.
- `infer_schema` (`:46`) samples 5,000 rows; a type that changes later in a
  large file is silently mis-modelled. Supersede with Task 3's full-file pass.
- No schema over the spec dict. `build_from_spec` calls `method_fn(**vs)` bare,
  so a missing key surfaces as
  `TypeError: add_card_measure() missing 1 required positional argument: 'table'`.
  A `spec_schema.py` with friendly, field-named errors would pay for itself.

## How to report

One PR per task, smallest first. In each PR description state plainly:

1. What you changed and why.
2. What you verified, and the command that proves it.
3. **What you could not verify without Power BI Desktop.** This is the most
   useful line in the PR — it is the Windows checklist.

If a task turns out to be larger than described, stop and say so rather than
half-landing it. If you find a defect outside your current task, write it down
and keep going; do not widen the PR.

## Out of scope

Do not attempt these — they need Windows, Power BI Desktop, or a decision that
is not yours:

- Opening, refreshing or rendering any `.pbip`
- Embedding data as gzipped base64 in the TMDL (untested against Desktop's
  parser; a Windows experiment comes first)
- Swapping fonts, or changing the designed-background geometry
- Publishing, releasing, or changing repository visibility
